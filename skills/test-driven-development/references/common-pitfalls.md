# Common TDD Pitfalls

Avoid these:

1. Writing production code before a failing test exists.
2. Writing overly broad tests that pass for the wrong reasons.
3. Testing implementation details instead of observable behavior.
4. Skipping the refactor step and accumulating technical debt.
5. Adding multiple behaviors in a single Red-Green cycle.
6. Changing production code without first having a failing test that forces the change.
7. Ignoring flaky or non-deterministic tests.
8. Treating tests as an afterthought rather than the specification.
